# 04 计算机系统

这一章是 CS 本科的“硬核”部分，也是区分“会调包”和“懂计算机”的分水岭。每一门课单独看都像一座山，合起来看其实是一条线：**从底层的晶体管，到顶层的应用，中间每一层都在为上一层提供抽象、同时隐藏细节**。合格的标准是：你能沿着这条线上下走——从上往下知道“我的代码最后变成了什么”，从下往上知道“这一层为什么要这样抽象”。

## 4.1 计算机组成原理：知道代码最后变成了什么

**为什么需要它**：性能问题最终都是硬件问题。缓存、流水线、内存层次结构——不懂这些，你写的“优化”只是在猜。

**合格线**：

- 数据的表示：二进制、补码、浮点数（IEEE 754）、为什么 `0.1 + 0.2 != 0.3`
- 指令集与汇编：能读简单的汇编，理解“高级语言的一行代码对应多条机器指令”
- CPU：流水线、分支预测、超标量——知道它们为什么存在，以及“分支预测失败”为什么会让程序变慢
- 内存层次结构：寄存器、L1/L2/L3 缓存、内存、磁盘——理解局部性原理（时间局部性、空间局部性），知道“缓存友好”的代码长什么样
- I/O 与中断：知道程序是怎么和外设打交道的

**关键概念清单**：补码、IEEE 754、流水线冒险、缓存行、缓存命中率、局部性原理、DMA、中断。

**推荐资源**：

- Randal E. Bryant《深入理解计算机系统》（CSAPP）——这本书是这一章的半壁江山，第 2、3、6 章必读
- David A. Patterson《计算机组成与设计》（Computer Organization and Design）——更系统的教材
- CMU 15-213 Introduction to Computer Systems（公开课）——CSAPP 的配套课，实验极好

## 4.2 操作系统：资源管理的艺术

**为什么需要它**：你写的每一个程序都跑在操作系统上。进程、线程、内存、文件、网络——所有“程序和硬件之间”的事，都是操作系统在管。不懂操作系统，你就只能把性能问题和诡异 bug 归结为“玄学”。

**合格线**：

- 进程与线程：进程 vs 线程、上下文切换的代价、线程安全、死锁的四个必要条件
- 并发控制：互斥锁、信号量、条件变量——会用，更要知道“什么时候不该用”（无锁数据结构、消息传递）
- 内存管理：虚拟内存、分页、分段、页表、缺页中断、TLB——理解“每个进程都以为自己独占内存”这个幻觉是怎么造出来的
- 文件系统：inode、目录、日志文件系统、文件描述符
- 调度：进程调度算法（轮转、优先级、多级反馈队列）、I/O 调度
- 系统调用：知道用户态和内核态的边界，知道一次 `read()` 背后发生了什么

**优秀线**：读过一个小型操作系统内核（xv6）；理解虚拟化与容器的原理（namespace、cgroup）；能解释“为什么 fork 之后子进程和父进程看到的内存是一样的”。

**关键概念清单**：进程、线程、上下文切换、竞态条件、死锁、信号量、虚拟内存、分页、缺页中断、TLB、inode、系统调用、用户态/内核态。

**推荐资源**：

- Remzi Arpaci-Dusseau《操作系统导论》（Operating Systems: Three Easy Pieces，OSTEP）——免费在线，写得极好，首选
- Abraham Silberschatz《操作系统概念》（恐龙书）——体系最全的参考书
- MIT 6.828 / xv6——读一个真实的小内核，是理解操作系统的最快路径
- CSAPP 第 8、9、10 章——进程、虚拟内存、系统级 I/O 的精华

## 4.3 计算机网络：分布式世界的基础设施

**为什么需要它**：现代软件几乎都是分布式的。不懂网络，你就理解不了“为什么这个请求慢”、“为什么这个服务会超时”、“为什么数据会丢”。

**合格线**：

- 分层模型：OSI 七层 vs TCP/IP 四层——知道每一层解决什么问题，分层的好处和代价
- 应用层：HTTP（方法、状态码、缓存、HTTPS）、DNS、REST 的基本思想
- 传输层：TCP（三次握手、四次挥手、流量控制、拥塞控制、重传）vs UDP——知道 TCP 的可靠性是怎么换来的（代价是延迟和复杂度）
- 网络层：IP、路由、NAT、子网——知道数据包是怎么找到目的地的
- 链路层：以太网、Wi-Fi——了解即可
- 网络编程：Socket 编程、会写一个简单的客户端/服务器

**优秀线**：理解拥塞控制算法（Reno/CUBIC/BBR）的基本思想；能用 Wireshark 抓包分析一次真实的 HTTP 请求；理解 CDN、负载均衡、DNS 解析的完整链路。

**关键概念清单**：分层、封装、TCP 三次握手、滑动窗口、拥塞窗口、DNS 解析、HTTP 缓存、TLS 握手、NAT、子网掩码。

**推荐资源**：

- James F. Kurose《计算机网络：自顶向下方法》——从应用层往下讲，最符合直觉的教材
- 《TCP/IP 详解 卷 1》（W. Richard Stevens）——想深入时的参考书
- Stanford CS144 Introduction to Computer Networking（公开课）——配实验，极好
- 《HTTP 权威指南》——做 Web 开发时的案头书

## 4.4 数据库：数据的家

**为什么需要它**：几乎所有应用都要存数据。数据库是“数据持久化、一致性、并发”这三个难题的工业级答案。不懂数据库，你写的每个应用都会在数据量上去之后出问题。

**合格线**：

- 关系模型：表、主键、外键、范式（1NF/2NF/3NF）——知道范式在解决什么问题（冗余与更新异常），以及什么时候可以反范式
- SQL：增删改查、JOIN、聚合、子查询、窗口函数——能写中等复杂度的查询
- 索引：B+ 树索引、哈希索引、什么时候建索引、为什么索引不是越多越好
- 事务：ACID、隔离级别（读未提交/读已提交/可重复读/串行化）、脏读/不可重复读/幻读
-  NoSQL 入门：键值、文档、列族、图——知道它们各自适合什么场景，以及“什么时候不该用 NoSQL”
- 数据库设计：ER 图、从需求到表结构

**优秀线**：理解查询优化器是怎么工作的（执行计划、EXPLAIN）；理解 MVCC；从零实现一个简单的 KV 存储或 B+ 树。

**关键概念清单**：范式、主键/外键、JOIN、索引、事务、ACID、隔离级别、MVCC、查询优化、CAP 定理（入门）。

**推荐资源**：

- Abraham Silberschatz《数据库系统概念》——体系最全的教材
- CMU 15-445 Introduction to Database Systems（公开课）——讲得极好，实验是写一个数据库
- 《高性能 MySQL》——做后端时的案头书
- 《Redis 设计与实现》——理解内存数据库的好入口

## 4.5 编译原理：理解语言是怎么变成机器代码的

**为什么需要它**：编译原理是“把人类语言翻译成机器语言”的完整链条。学完它，你对编程语言的理解会从“会用”变成“懂原理”——报错信息、性能特征、语言设计取舍，全都说得清了。它也是最能体现“从零实现”价值的课：写一个小语言，是 CS 本科最值得做的项目之一。

**合格线**：

- 词法分析：正则表达式、有限自动机、词法单元（token）
- 语法分析：上下文无关文法、递归下降、LL/LR——知道“为什么有的语法写不出来”（二义性）
- 语义分析：作用域、类型检查、符号表
- 中间表示与优化：三地址码、常量折叠、死代码消除
- 代码生成：从中间表示到目标代码，寄存器分配入门

**优秀线**：从零实现一个带变量、函数、闭包的小语言（解释器或编译到字节码 + 虚拟机）；理解垃圾回收的基本算法（标记清除、复制、分代）。

**关键概念清单**：token、文法、递归下降、抽象语法树（AST）、符号表、类型检查、中间表示、寄存器分配、垃圾回收。

**推荐资源**：

- Alfred V. Aho《编译原理》（龙书）——经典教材，当参考书查
- Robert Nystrom《Crafting Interpreters》——免费在线，从零写两个解释器，是学编译最好的实践路径
- Andrew Appel《现代编译原理：C 语言描述》（虎书）——更贴近实现
- Stanford CS143 Compilers（公开课）——配实验，写一个完整编译器

## 本章总结

| 课程 | 合格的标志 | 最值得做的练手项目 |
|---|---|---|
| 组成原理 | 理解内存层次结构和流水线，知道性能问题最终是硬件问题 | 用 CSAPP 的实验做缓存攻击/优化 |
| 操作系统 | 理解进程/线程/虚拟内存/文件系统，能解释系统调用 | 读 xv6，写一个简单的 shell |
| 计算机网络 | 理解 TCP 的可靠性代价，会写 Socket 程序 | 写一个简单的 HTTP 服务器 |
| 数据库 | 会设计表结构、写复杂 SQL、理解事务隔离级别 | 从零写一个 KV 存储 |
| 编译原理 | 理解词法/语法/语义/代码生成的链条 | 从零写一个小语言 |

**一句话**：系统课的合格线不是“考试过了”，而是“能沿着抽象层次上下走，讲清每一层在干什么、为什么这样设计”。
