# 03 数据结构与算法

这一章是面试考得最多、也是最容易被误解的一章。先说清楚：**数据结构与算法不是为了面试才学的**。它真正的价值是：面对一个新问题，你脑子里有一个工具箱，知道“这类问题大概长什么样、该用什么工具、大概多快”。面试只是顺便考了这个能力。

## 3.1 必会的数据结构清单

分两层：第一层是“必须能从零实现”，第二层是“必须会用、知道代价”。

**第一层：必须能从零实现（白板上能写出来）**

| 结构 | 关键点 |
|---|---|
| 动态数组 | 扩容策略（为什么是翻倍）、均摊复杂度 |
| 链表（单/双） | 指针操作、哨兵节点、快慢指针 |
| 栈与队列 | 用途（调用栈、括号匹配、BFS），以及用两个栈实现队列这类经典变换 |
| 哈希表 | 哈希函数、冲突解决（链地址法 / 开放地址法）、负载因子与 rehash |
| 二叉搜索树 | 插入/删除/查找，知道它在最坏情况下会退化成链表 |
| 堆（优先队列） | 上浮/下沉、建堆为什么是 O(n) |
| 图的表示 | 邻接矩阵 vs 邻接表，什么时候用哪个 |
| 并查集 | 路径压缩 + 按秩合并，均摊近乎 O(1) |
| Trie | 前缀匹配、自动补全的经典结构 |

**第二层：必须会用、知道代价**

- 平衡树（红黑树 / AVL）：知道它们解决什么问题（BST 退化），知道标准库里的有序容器（C++ `std::map`、Java `TreeMap`）背后是什么，不要求手写红黑树
- B 树 / B+ 树：知道它们为什么是数据库索引的默认选择（磁盘友好）
- 布隆过滤器：知道它能做什么（快速判断“一定不在”）、不能做什么（不能删除、有假阳性）
- 跳表：知道它是平衡树的简单替代品（Redis 的有序集合就用它）
- 线段树 / 树状数组：区间查询问题知道有这类工具即可，做竞赛之外很少手写

**合格线**：第一层全部能白板实现并讲清复杂度；第二层能在具体场景里选出正确的结构，并讲清“为什么不用别的”。

## 3.2 必会的算法思想清单

算法思想比具体算法重要。具体算法会忘，思想不会：

| 思想 | 核心问题 | 代表算法 |
|---|---|---|
| 分治 | 能不能把问题拆成独立的小问题？ | 归并排序、快速排序、二分查找 |
| 贪心 | 局部最优能不能推出全局最优？（关键：证明） | 活动选择、Huffman 编码、Dijkstra |
| 动态规划 | 有没有重叠子问题和最优子结构？ | 背包、LCS、最短路、编辑距离 |
| 回溯 / 搜索 | 解空间太大，能不能剪枝？ | N 皇后、数独、子集生成 |
| 图算法 | 问题能不能翻译成图？ | BFS/DFS、拓扑排序、最小生成树、最短路 |
| 排序与查找 | 比较排序的下界是 Ω(n log n)，什么时候能突破？ | 计数排序、基数排序（非比较排序） |
| 字符串算法 | 模式匹配、子串问题 | KMP、Rabin-Karp、后缀数组（了解） |
| 随机化 | 随机性能不能把最坏情况变成期望好？ | 快速排序随机 pivot、随机化快排、蒙特卡洛 |

**合格线**：看到一个新问题，能先判断“它像哪类思想的问题”，再动手；能讲清贪心和动态规划的适用条件区别（贪心需要贪心选择性质，DP 需要最优子结构 + 重叠子问题）。

## 3.3 复杂度分析：必须会的两件事

1. **会算**：给定一段代码，能算出时间复杂度和空间复杂度（最好、最坏、平均、均摊）。会用主定理（Master Theorem）分析分治递归。
2. **会估**：给定数据规模（n = 10^5、10^6、10^7），能立刻判断 O(n²) 行不行、O(n log n) 行不行。记住这张速查表：

| n 的规模 | 1 秒内可接受的复杂度 |
|---|---|
| n ≤ 10 | O(n!)、O(2^n) |
| n ≤ 20–25 | O(2^n) |
| n ≤ 10^3 | O(n²) |
| n ≤ 10^5 | O(n log n) |
| n ≤ 10^6–10^7 | O(n)、O(n log n) |
| n ≤ 10^8 | O(n) |
| n 更大 | O(log n)、O(1)，或者换思路 |

**常见误区**：只会背“快排 O(n log n)”，不知道它最坏是 O(n²) 以及为什么实践中很少遇到最坏情况；只会算时间复杂度，忽略空间复杂度（递归深度导致的栈溢出是真实生产事故）。

## 3.4 刷题建议：数量级和方法

**先说结论**：刷题有用，但题海战术是效率最低的学习方法。目标是 150–300 道题，不是 1000 道。

**方法（按顺序）**：

1. **按类型刷，不按难度刷**。先刷完一个类型（比如“双指针”）的 10 道题，再换下一个类型。类型内化了，难度自然上去。
2. **每道题三个阶段**：先自己想 20 分钟（想不出来再看题解，这是正常的）；看懂题解后关掉题解自己写一遍；一周后不看答案再写一遍。三个阶段缺一个，效果打对折。
3. **写题解笔记**：每道题一句话——“这道题的关键是发现 X”。三个月后复习，只看这一句话。
4. **刻意练薄弱类型**：动态规划和图论是最常见的薄弱项，单独加练。
5. **模拟面试**：每周至少一次，在白板或共享文档上、限时 30 分钟、一边讲思路一边写代码。面试考的不是“会不会”，是“能不能在压力下讲清楚”。

**数量参考**：

| 目标 | 建议题量 |
|---|---|
| 毕业合格（能通过一般公司面试） | 150 道，按类型覆盖 |
| 优秀（能通过大厂面试） | 300 道，含 Hard 50 道以上 |
| 顶尖（竞赛 / 顶级公司） | 500+ 道，另加专项训练 |

**不要做的事**：

- 不要只刷 Easy 题自我安慰。Easy 题练的是手感，不是思维。
- 不要背答案。面试官换个条件你就不会了，背答案是最脆弱的准备。
- 不要为了刷题放弃做项目。面试里“讲项目”的权重和“做题”至少是一半一半。

**推荐资源**：

- Thomas H. Cormen 等《算法导论》（CLRS）——最全面的教材，读重点章节即可，不必通读
- Robert Sedgewick《算法》（Algorithms）——更贴近实现，配图极好
- LeetCode 经典题单（按类型刷）；《代码随想录》作为中文辅助
- MIT 6.006（现 6.1210）Introduction to Algorithms（公开课）——讲得极清楚，适合入门
- William Fiset 的算法视频（YouTube）——可视化做得好，适合理解

## 自测题

1. **白板实现**：在纸上（不用 IDE）实现一个哈希表：链地址法解决冲突、负载因子超过 0.75 时 rehash。验证：照着纸上的代码敲进电脑，写测试验证插入、查找、删除、rehash 都正确。
2. **复杂度估算**：给定 n = 10^6，判断三段代码（O(n²)、O(n log n)、O(n)）哪段能在 1 秒内跑完，并实际计时验证。验证：实测结果和你的判断一致，能说出机器常数带来的误差范围。
3. **思想识别**：找一道没做过的背包变体题，先写出状态定义和转移方程（不写代码），再写代码。验证：测试通过；能说出“为什么这题是 DP 而不是贪心”。

## 本章总结

| 能力 | 合格的标志 |
|---|---|
| 数据结构 | 第一层白板能写，第二层会选型、讲清代价 |
| 算法思想 | 见到新问题能判断属于哪类思想 |
| 复杂度 | 会算、会估，知道数据规模决定算法选择 |
| 刷题 | 150–300 道按类型刷过，能讲清思路 |

**一句话**：数据结构与算法的合格线不是“刷了多少题”，而是“脑子里有一个工具箱，见到新问题知道该掏哪件工具”。
