# 07 工具链

工具链不是“锦上添花”，而是“每天都要用的手”。工具用得顺，一天能省一小时；工具用不顺，每天都在和工具较劲。这一章的目标很实际：**让你每天的工作流顺滑到感觉不到工具的存在**。

## 7.1 编辑器 / IDE：选一个，用到底

**合格线**：

- 精通一个编辑器或 IDE（VS Code、IntelliJ、Neovim、Emacs 都行），做到：快捷键不用想、跳转定义和找引用是肌肉记忆、能配好 lint 和格式化、能同时开多个项目不乱。
- 知道编辑器和 IDE 的区别：编辑器轻、启动快、配起来灵活；IDE 重、开箱即用、重构和调试更强。没有对错，只有适合。
- 会配开发环境：语言服务器（LSP）、调试配置、代码片段——配一次，受益四年。验证标准：不用鼠标完成一次重构（改名、提取函数、移动文件），中途不卡壳。

**常见误区**：

- 频繁换编辑器。每个编辑器都有学习成本，换一次等于把肌肉记忆清零一次。选一个，用三年。
- 花太多时间“折腾配置”。配置的边际收益递减很快：配到“顺手”就停手，剩下的时间写代码。
- 只用鼠标不用键盘。鼠标点来点去，一天下来比键盘慢一个小时不止。

## 7.2 命令行：程序员的第二语言

**合格线**：

- Shell 基础：管道、重定向、通配符、环境变量、后台任务——不靠图形界面能完成日常操作。
- 常用工具：`grep` / `rg`（搜索）、`sed` / `awk`（文本处理）、`find`（找文件）、`curl`（发请求）、`jq`（处理 JSON）、`ssh` / `scp`（远程操作）。
- 会写简单的 Shell 脚本：把重复操作自动化，而不是每次手动敲十条命令。
- 会用 tmux 或 screen：远程会话断了，工作不丢。

**优秀线**：会用 `git` 的高级操作（bisect、reflog、cherry-pick）；会写 Makefile 或任务脚本；知道什么时候该用脚本、什么时候该写个小程序。

**一句话**：命令行不是“复古”，是“精确”。图形界面点十下做的事，命令行一行就做完了，而且可重复、可记录、可自动化。

## 7.3 Docker 与虚拟化：环境一致性的答案

**合格线**：

- 理解容器和虚拟机的区别：容器共享宿主机内核、轻量、启动快；虚拟机完整隔离、更重。
- 会写 Dockerfile：从基础镜像开始，装依赖、拷代码、设入口，能把自己的项目容器化。
- 会用 docker compose（新版命令，旧写法是 docker-compose）把“应用 + 数据库 + 缓存”一键跑起来。
- 知道镜像体积为什么重要，以及多阶段构建是怎么瘦身的。

**优秀线**：理解 Kubernetes 的基本概念（Pod、Service、Deployment）；知道容器网络和存储是怎么工作的；能排查容器里的常见问题（端口不通、时区不对、文件权限）。

**常见误区**：把 Docker 当成“部署神器”却不理解它——容器里出问题就只会重启。理解原理之后，90% 的容器问题一眼就能定位。

## 7.4 调试与性能分析工具：从“猜”到“测”

**合格线**：

- 调试器：断点、单步、条件断点、调用栈——02 章已经讲过，这里是工具层面的落实。
- 日志：会打有用的日志（时间、级别、上下文、关键变量），知道“日志不是越多越好”。
- 性能分析：会用 profiler（Go pprof、Python cProfile、perf、VisualVM 等）找到热点，而不是凭感觉优化。
- 内存分析：会用工具找内存泄漏（valgrind、AddressSanitizer、语言自带的工具）。

**优秀线**：会读火焰图（flame graph）；会用 strace / tcpdump / Wireshark 从系统调用和网络包层面定位问题；知道“先测量、再优化”是铁律——没测过的优化，都是猜测。

**一句话**：性能优化的第一步永远是测量。凭感觉优化，十次里有九次优化了不该优化的地方。

## 7.5 文档与笔记：第二大脑

**合格线**：

- 有一套自己的笔记系统（Obsidian、Notion、纯 Markdown 文件都行），并真的在用——学到的东西当天就记下来。
- 笔记的原则：记“自己的理解”，不是抄书。抄来的东西过一周就忘，自己的话记得住。
- 会写技术文档：README、设计文档、故障复盘（postmortem）——写清楚“发生了什么、为什么、怎么修的、下次怎么避免”。

**优秀线**：公开写技术博客（一年 6 篇以上）；能把复杂的东西讲简单——这是检验自己真懂了的最好方法。

**常见误区**：收藏了几百篇文章，一篇都没读完。收藏不是学习，读完、理解、记下来才是。

## 7.6 版本管理与包管理：别在这上面翻车

- **Git**：见 05 章。
- **包管理**：会用所在语言的包管理器（pip/uv、npm、go mod、cargo、Maven），知道锁文件（lock file）是干什么的——“在我机器上能跑”不够，要“在任何机器上都能复现”。
- **环境管理**：虚拟环境、版本切换工具（pyenv、nvm、rustup）——不同项目用不同版本时不互相污染。

## 推荐资源

- William Shotts《The Linux Command Line》——免费在线，命令行的系统入门
- 鸟哥《鸟哥的 Linux 私房菜》——中文世界最经典的 Linux 入门书
- Docker 官方文档 Get Started——跟着走一遍，比看二手教程可靠
- Brendan Gregg《Systems Performance》——性能分析的案头书，火焰图、测量方法都在里面

## 自测题

1. **全键盘工作流**：不用鼠标完成一次完整工作：新建分支、改代码、跑测试、提交、推送。验证：全程没碰鼠标；快捷键卡住的地方记下来，练到不卡为止。
2. **容器化**：把自己的一个项目写成 Dockerfile + docker compose 配置，在一台干净机器（或新容器）上只用一条命令跑起“应用 + 数据库”。验证：换一台机器照样跑通。
3. **先测后优**：用 profiler 找到自己项目里的一个真实热点，优化后拿出优化前后的测量数字，证明它真的变快了。验证：有两组数字（优化前 / 优化后），且优化点就是 profiler 指出的热点。

## 本章总结

| 工具 | 合格的标志 |
|---|---|
| 编辑器/IDE | 一个用到底，快捷键是肌肉记忆 |
| 命令行 | 日常操作不靠图形界面，会写脚本自动化 |
| Docker | 会把自己的项目容器化，一键跑起来 |
| 调试与性能分析 | 会用 profiler 找热点，先测量再优化 |
| 文档与笔记 | 有在用的笔记系统，学到的东西当天记 |
| 包与环境管理 | 锁文件、虚拟环境，复现性有保障 |

**一句话**：工具链的目标是“感觉不到工具的存在”——你的注意力应该在问题上，不在工具上。
