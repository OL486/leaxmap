# 06 方向选修

先说最重要的前提：**前面五章是地基，这一章是加分项，不要倒置。**

方向选得再好，地基不牢也走不远。一个数据结构都写不利索的人去追大模型，一个操作系统都没学明白的人去搞分布式，最后都会发现：面试官问的深问题，全在地基里。方向决定你“走多快”，地基决定你“走多远”。

选方向的原则：

1. **先广后深**：大一、大二广泛接触，大三再定方向。过早定方向等于闭着眼睛选。
2. **跟着兴趣和反馈走**：对哪个方向“做起来不觉得累、还想继续做”，就往哪个方向走。兴趣不是选出来的，是试出来的。
3. **一个方向做深，胜过五个方向都沾一点**。简历上“五个方向都了解”是最弱的信号。

下面每个方向都按同一个结构写：核心知识、入门路径、适合什么样的人。

## 6.1 AI / 机器学习

**核心知识**：线性代数、概率统计、优化（梯度下降）、机器学习基础（监督/无监督、过拟合、交叉验证）、深度学习（神经网络、反向传播、CNN/RNN/Transformer）、至少一个框架（PyTorch 为主）。

**入门路径**：先补数学（01 章的线代和概率），再看吴恩达的机器学习课程入门，接着用 PyTorch 跑通一个真实数据集的项目（分类、回归都行），最后读一篇经典论文并复现它。

**适合什么样的人**：数学不讨厌、喜欢从数据里找规律、能忍受“调参调一天结果只好了 0.5%”的人。

**诚实提醒**：AI 方向的门槛在快速提高——只会调包已经不够了。数学和系统能力（能把模型训起来、部署上去）才是护城河。只会 `model.fit()` 的人，和只会调 API 的人一样脆弱。

**延伸阅读**：李沐等《动手学深度学习》（Dive into Deep Learning，免费在线）——边看边跑代码，是 AI 入门最扎实的路径。

## 6.2 后端开发

**核心知识**：一门后端语言（Go/Java/Python）、HTTP/REST、数据库（SQL + 索引 + 事务）、缓存（Redis）、消息队列、并发编程、系统设计。

**入门路径**：先写一个带数据库的完整后端项目（用户、鉴权、CRUD），再学缓存和消息队列解决性能问题，接着学系统设计（怎么拆服务、怎么做限流熔断），最后读一个开源后端项目的源码。

**适合什么样的人**：喜欢“把系统搭起来、让它稳定运行”的人；对性能和可靠性有执念的人。

**诚实提醒**：后端最容易陷入“只会调框架”——框架会换，网络、数据库、并发才是地基。面试官问深了，问的永远是地基。

**延伸阅读**：Martin Kleppmann《设计数据密集型应用》——后端绕不开的数据、缓存、一致性问题，这本书一次讲清。

## 6.3 前端开发

**核心知识**：HTML/CSS/JavaScript、TypeScript、一个主流框架（React/Vue）、浏览器原理（渲染、事件循环）、网络基础（HTTP、缓存）、工程化（构建、打包、测试）。

**入门路径**：先手写不用框架的页面（理解 DOM 和事件），再学一个框架做完整项目，接着学性能优化（懒加载、缓存策略），最后理解浏览器渲染管线。

**适合什么样的人**：对用户体验敏感、喜欢“所见即所得”、审美不差的人。

**诚实提醒**：前端框架换得最快，不要追框架。浏览器原理、JavaScript 语言本身、网络基础——这些十年不变的东西才是地基。

**延伸阅读**：MDN Web Docs——前端最权威的免费参考；Nicholas C. Zakas《JavaScript 高级程序设计》——把 JS 语言本身学透。

## 6.4 系统 / 基础设施（Infra）

**核心知识**：操作系统、计算机网络、分布式系统、容器（Docker/Kubernetes）、云计算、性能分析、存储系统。

**入门路径**：先把 04 章的系统课学扎实，再从零实现一个小系统（KV 存储、一个简单的分布式共识比如 Raft、HTTP 服务器），接着读一个工业级系统的源码（etcd、Redis、TiDB），最后参与开源基础设施项目。

**适合什么样的人**：喜欢钻到底层、享受“搞清楚它到底怎么工作”的人；对性能数字敏感的人。

**诚实提醒**：这是回报周期最长的方向，也是越老越吃香的方向。前两年会觉得“学的东西面试不考”，第三年开始会发现别人追不上你。

**延伸阅读**：Betsy Beyer 等《SRE：Google 运维解密》（Site Reliability Engineering，免费在线）——infra 方向的工程实践集大成。

## 6.5 安全

**核心知识**：网络协议、操作系统、密码学基础、Web 安全（XSS、CSRF、SQL 注入）、二进制安全（逆向、漏洞分析）、安全工程（威胁建模、审计）。

**入门路径**：先学好网络和操作系统，再系统学 Web 安全（OWASP Top 10），接着打 CTF 练手，最后选一个细分方向深入（二进制、Web、密码学、云安全）。

**适合什么样的人**：好奇心强、喜欢“找系统哪里不对劲”、有耐心抠细节的人。

**诚实提醒**：安全方向的入门门槛比看起来高——它要求你对系统有整体理解。没有系统地基的安全学习，很容易变成“会用工具扫描、不会分析原理”。

**延伸阅读**：Dafydd Stuttard、Marcus Pinto《黑客攻防技术宝典：Web 实战篇》——Web 安全的案头书，讲原理也讲手法。

## 6.6 图形学

**核心知识**：线性代数、微积分、光线追踪、光栅化、着色器（GLSL）、图形 API（OpenGL/Vulkan）、物理模拟入门。

**入门路径**：先补数学（线代必须扎实），再跟着教程写一个光线追踪器（Ray Tracing in One Weekend），接着学 OpenGL 做实时渲染，最后读一个渲染引擎的源码。

**适合什么样的人**：数学好、审美在线、喜欢“把数学变成画面”的人。

**诚实提醒**：图形学见效慢，第一个渲染器可能丑得没法看。坚持过去才有回报，半途而废的人最多。

**延伸阅读**：Peter Shirley 等《Fundamentals of Computer Graphics》——图形学的系统教材，配合光线追踪器一起读。

## 6.7 嵌入式 / 物联网

**核心知识**：C 语言、计算机组成、操作系统（实时系统）、硬件接口（GPIO、I2C、SPI）、低功耗设计、通信协议。

**入门路径**：先学好 C 和组成原理，再买一块开发板（STM32/ESP32）做项目，接着学实时操作系统（FreeRTOS），最后做一个完整的软硬件结合的项目。

**适合什么样的人**：喜欢动手、能忍受“调硬件比调软件慢十倍”的人；对物理世界有兴趣的人。

**诚实提醒**：嵌入式的调试周期以天计，买开发板之前先想清楚：每周能不能拿出固定的时间投入。

**延伸阅读**：Elecia White《Making Embedded Systems》——嵌入式入门最实用的书，从“点亮一个灯”讲到“设计一个系统”。

## 6.8 其他方向（知道存在即可）

- **数据工程 / 数据分析**：SQL、数据仓库、ETL、数据可视化。适合喜欢和数据打交道的人。
- **游戏开发**：图形学 + 引擎 + 游戏设计。适合热爱游戏且数学好的人。
- **编译器 / 编程语言**：类型系统、代码生成、语言设计。适合喜欢抽象和理论的人。
- **人机交互（HCI）**：心理学 + 设计 + 前端。适合对“人怎么用软件”有兴趣的人。
- **生物信息学 / 计算科学**：交叉学科，适合有明确交叉兴趣的人。

## 自测题

1. **讲 10 分钟**：按选定方向做一个项目，不看稿讲 10 分钟：它解决什么问题、为什么这样设计、放弃了什么备选方案。验证：听的人能复述出三个设计决策及其理由。
2. **读论文/文档**：读一篇该方向的经典论文（或官方文档的核心章节），写 500 字复述：它解决什么问题、trade-off 是什么、局限在哪。验证：没读过这篇论文的人读完你的复述能听懂。
3. **质疑流行做法**：找到该方向一个你不同意的流行做法，写出你的理由和替代方案，理由必须基于实测数据或原理推导，不能是“我感觉”。验证：理由能经得起一次追问。

## 本章总结

| 方向 | 最核心的前置 | 一句话判断适不适合 |
|---|---|---|
| AI/ML | 线代、概率、优化 | 数学不讨厌，耐得住调参 |
| 后端 | 网络、数据库、并发 | 喜欢把系统搭起来跑稳 |
| 前端 | JS、浏览器、网络 | 对体验敏感，审美在线 |
| 系统/Infra | 操作系统、网络、分布式 | 喜欢钻到底层，越老越吃香 |
| 安全 | 网络、操作系统、密码学 | 好奇心强，喜欢找毛病 |
| 图形学 | 线代、微积分 | 数学好，想把数学变成画面 |
| 嵌入式 | C、组成、硬件 | 喜欢动手，不怕调硬件慢 |

**一句话**：方向是加分项，地基是必答题。先把地基打到“毕业合格”，再选一个方向做到“优秀”。
