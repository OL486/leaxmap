# leaxmap

> 一名合格的 CS（计算机科学本科生）需要什么？

这是一份给计算机科学本科生的知识地图 + 自查清单。它不教你怎么写某一行代码，而是回答一个更根本的问题：**四年下来，你应该长成什么样，才算“合格”？**

## “合格”是什么意思

“合格”不是一个点，而是一条线。我们把它分成三档：

| 档位 | 定义 | 检验标准 |
|---|---|---|
| **毕业合格** | 能独立完成常规开发任务，看得懂别人的代码，遇到没见过的问题知道怎么查、怎么拆 | 实习或课程设计里不拖后腿；能独立交付一个完整的小项目 |
| **优秀** | 对计算机系统有整体理解，能讲清“为什么这样设计”，能独立做技术选型 | 面试时能讲清做过的项目的每一个设计决策；能带一个小项目从 0 到 1 |
| **顶尖** | 在一个方向上有深度，能读论文、能造轮子、能指出流行方案的边界 | 能从零实现一个小语言 / 数据库 / 服务器，并讲清它和工业实现的差距在哪 |

三档是递进关系，不是三条平行线。**先站稳“毕业合格”，再谈“优秀”。** 没有地基的方向选择，都是空中楼阁。

一个诚实的提醒：这份地图覆盖的是“本科四年应该长成的样子”，不是“三个月速成”。任何承诺速成的路线图，都在骗你。

## 如何使用本仓库

1. **第一次读**：先读完本 README，再按顺序读 01–05 章。06 章先浏览一遍，知道有哪些方向即可，不要急着选。
2. **自评**：打开 [checklist.md](checklist.md)，诚实地打勾。打勾的标准在每项后面：了解 / 熟悉 / 掌握 / 精通四个档位，只按你能做到的最高档打勾。
3. **补短板**：对着 checklist 里没打勾的项，去对应章节找合格线和推荐资源，一项一项补。
4. **定期复评**：每个学期末重新打一遍勾。地图不会变，变的是你。

## 三条红线：不要过早做的事

- **不要大一就追新框架**。框架三个月一换，地基十年不变。先把编程、数据结构、系统学扎实，框架一周就能上手。
- **不要只刷题不做项目**。刷题证明你会解题，做项目证明你会交付。面试官和未来的同事，更关心后者。
- **不要用“看过”代替“会”**。看完一本书、刷完一个视频，不等于掌握。合格线的唯一标准是：不看答案，能独立做出来、讲清楚。
